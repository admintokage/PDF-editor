# PDF-editor 要件定義書

- 作成日: 2026-11-13
- 状態: 依頼者の確認待ち
- 表記: 【依頼者決定】は依頼者が会話で決めたこと。【作成者判断】は作成者（Claude）が選んだ初期案で、依頼者の合意はまだ取っていない。

## 1. 目的と背景

無料の Adobe Acrobat Reader では PDF の閲覧とコメント追加しかできない。PDF の中身そのもの（文字、画像、ページ構成）を手軽に直せる、無料の Windows 用エディタを作り、依頼者本人と周囲の人に配る。【依頼者決定】

想定する使い方は、Word などから作った横書きの PDF を開き、文章を直し、不要な部分を黒塗りし、ページを入れ替え、ヘッダー・フッターを付けて保存する、という一連の作業である。

## 2. 利用者と環境

| 項目 | 内容 |
|---|---|
| 利用者 | 依頼者と、依頼者が配布する相手。PDF の内部構造の知識はない前提【依頼者決定：配布する】 |
| OS | Windows 10 / 11（64bit）【依頼者決定：Windows。版と 64bit 限定は作成者判断】 |
| 導入 | 管理者権限でのインストール不要。渡されたものを展開して実行ファイルをダブルクリックすれば動く【依頼者決定】 |
| 通信 | PDF を外部に送らない。全処理を手元の PC 内で行い、ネット接続なしで全機能が動く【依頼者決定】 |
| 費用 | 無料で配布する。有料の部品は使わない【依頼者決定】 |
| 画面の言語 | 日本語のみ【作成者判断】 |
| Windows の言語 | 日本語版 Windows を前提とする【作成者判断】 |

## 3. 対象とする PDF

| 種類 | 扱い |
|---|---|
| Word などから作った横書きの PDF | 主対象。全機能が使える【依頼者決定】 |
| スキャン PDF（中身が画像） | 文字の打ち替えは対象外。画像・テキスト・図形の追加、黒塗り、ページ操作、ヘッダー・フッターは使える |
| 縦書き、段組み、複雑な表の中の文章 | 表示と、文字の打ち替え以外の機能は使える。段落の流し直しは保証しない |
| 文字が図形に変換されている PDF | 文字の打ち替えは対象外 |
| パスワード付き PDF | 開くときにパスワードを尋ねる。編集制限だけが掛かった PDF は、権限パスワードの入力を求める【作成者判断】 |
| 電子署名付き PDF | 編集すると署名が無効になる旨を警告してから編集を許す【作成者判断】 |

## 4. 機能要件

### 4.1 開く・表示する

- F-01 PDF をファイル選択、ドラッグ＆ドロップ、実行ファイルへのドロップで開ける。
- F-02 ページを連続スクロールで表示し、拡大・縮小、幅に合わせる、ページ全体表示ができる。
- F-03 左側にページのサムネイル一覧を出す。
- F-04 一度に開く文書は 1 ウィンドウに 1 つ。複数開くときはウィンドウを分ける【作成者判断】。

### 4.2 既存の文字の打ち替え【依頼者決定：必須】

- F-10 ページ上の文章をクリックすると、その段落が編集枠になり、その場で文字を打ち替えられる。
- F-11 編集単位は段落。アプリが文字の並びから段落の範囲を推定する。
- F-12 文字数が変わると、枠の幅の中で自動的に折り返しをやり直す【依頼者決定】。1 文字直しただけでも、その段落の中の改行位置や字間が元と変わることは許容する。行頭に句読点や閉じ括弧が来ないようにする基本的な禁則処理は必須とする。両端揃えの再現は努力目標とする【作成者判断】。
- F-12a 編集中の画面に見えている折り返しと、保存した PDF の折り返しは一致させる。
- F-13 編集枠は移動、幅・高さの変更ができる。推定した段落範囲が違う場合に、隣の段落と結合・分割できる。
- F-14 文章が増えて枠に収まらない場合、下に空きがあれば枠を下に伸ばす。空きがなく他の内容と重なる場合は警告を出し、利用者が枠の調整、文字サイズの縮小、そのまま確定のいずれかを選ぶ【作成者判断】。
- F-15 編集した段落より下にある内容を自動で押し下げること、次のページへ文章を送ることはしない（非目標 6 章）。
- F-16 編集しなかった段落は、見た目と、コピー・検索で取り出せる文字が元と変わらない。PDF 内部の記録のされ方まで一致することは求めない【作成者判断】。
- F-18 元の PDF から文字を正しく取り出せない段落（コピーすると文字化けする PDF）は、開いた時点で検出し、その段落は打ち替え不可として理由を表示する【作成者判断】。
- F-17 元の段落の書式（フォント、サイズ、色、行間、行揃え、太字・斜体）をできる限り引き継ぐ。段落内で書式が混在している場合も、文字ごとの書式を保つ。

### 4.3 フォントの指定と変更【依頼者決定】

- F-20 選択した文字のフォント、サイズ、色、太字、斜体、下線を変えられる。
- F-21 フォントの候補は、PC にインストールされているフォントの一覧とする。
- F-22 保存時、使ったフォントは使った文字だけを PDF に埋め込む。相手の PC にフォントがなくても同じ見た目になる。
- F-23 フォントファイルに記録された埋め込み許可を確認し、「埋め込み不可」と「印刷・プレビューのみ可」のフォントは候補に出さない【作成者判断】。

### 4.4 フォントが PC にないときの置き換え【依頼者決定】

背景：PDF に埋め込まれたフォントは、その PDF で使われている文字の分しか入っていないことが多い。同じフォントが PC にないと、新しい文字を同じフォントで打てない。

- F-30 PDF を開いた時に、PDF で使われているフォントのうち PC にインストールされていないものを一覧にしたダイアログを出す。足りないフォントがなければ出さない。
- F-31 一覧には元のフォント名をそのまま表示する。
- F-32 フォントごとに、代わりに使うフォントを選べる。初期値は游ゴシックまたは游明朝とする。
- F-33 初期値の決め方：元のフォント名や種類から明朝系と判断できれば游明朝、それ以外は游ゴシック【作成者判断】。
- F-33a 游明朝は Windows の追加機能扱いで、入っていない PC がありうる。ない場合は MS 明朝、それもなければ游ゴシックを初期値にする【作成者判断】。
- F-34 「足りない文字だけ別フォントで補う」ことはしない【依頼者決定】。置き換えは段落単位で行い、該当フォントを使う段落を編集した場合、その段落の該当フォント部分をすべて代わりのフォントで組み直す。
- F-35 置き換えの対象は編集した段落だけとする。触っていない段落は元の埋め込みフォントのまま表示・保存する【依頼者決定】。
- F-36 置き換えの設定は、後からメニューで開いて変更できる。
- F-37 フォント名ごとの置き換え設定を PC に記憶し、次に同じフォント名が出たら初期値として使う【作成者判断】。

### 4.5 テキストの追加【依頼者決定】

- F-40 ページ上の任意の場所にテキスト枠を置き、文字を入力できる。枠内で自動的に折り返す。
- F-41 フォント、サイズ、色、太字、斜体、下線、行揃えを指定できる。
- F-42 追加したテキスト枠は、保存して開き直した後も 4.2 の方法で編集できる。

### 4.6 画像の追加【依頼者決定】

- F-50 PNG、JPEG の画像をファイル選択、ドラッグ＆ドロップ、クリップボードからの貼り付けで追加できる。
- F-51 移動、拡大・縮小（縦横比の固定が既定）、回転（90 度単位）、削除ができる。
- F-52 PNG の透明部分は透明のまま扱う。
- F-53 既にある画像の移動・削除・差し替えは、初版では削除のみ対応する【作成者判断】。
- F-54 このアプリで追加した画像は、保存して開き直した後も選択・移動・大きさ変更・削除ができる【作成者判断】。

### 4.7 図形の追加【依頼者決定：長方形と楕円は必須】

- F-60 長方形と楕円を追加できる。
- F-61 枠線の有無、色、太さを指定できる。
- F-62 塗りつぶしの有無と色を指定できる。
- F-63 移動、大きさの変更、削除ができる。
- F-64 直線・矢印も追加できる【作成者判断：必須ではない】。
- F-65 このアプリで追加した図形は、保存して開き直した後も選択・移動・大きさ変更・色の変更・削除ができる【作成者判断】。他のソフトで見たときは、ページに描かれた普通の図形として見える。

### 4.8 黒塗り削除【依頼者決定】

- F-70 範囲をドラッグで囲む、または文字を選択して、黒塗りの対象に指定できる。
- F-71 指定した段階では「黒塗り予定」として枠だけを表示し、取り消せる。
- F-72 「黒塗りを実行」で、対象範囲を黒い長方形で覆い、同時にその下にあった文字データと画像の該当部分を PDF から完全に取り除く。保存した PDF から、コピー、検索、他のソフトでの解析によって元の内容を取り出せないこと【作成者判断：依頼者の「黒塗り削除」を完全な除去と解釈】。
- F-73 実行前に「元に戻せない」ことを確認する。実行後もアプリを閉じるまでは「元に戻す」で戻せるが、保存したファイルからは戻せない。
- F-74 塗りの色は黒が既定で、変更できる【作成者判断】。
- F-75 範囲に少しでも掛かる文字は、その文字ごと取り除く。画像は範囲に掛かる部分だけを消す。
- F-76 範囲に一部だけ掛かる線画（罫線、グラフ、図形化された文字など）は、漏れを防ぐことを優先し、範囲の外にはみ出す分も含めて線画ごと取り除く。実行前の確認画面で、消える線画を示す【作成者判断】。
- F-77 範囲に重なる注釈、リンク、フォームの入力値も取り除く【作成者判断】。
- F-78 しおりや文書情報（題名・作成者など）に同じ語句が残ることは黒塗りの対象外とし、実行時にその旨を知らせる【作成者判断】。

### 4.9 ページ操作【依頼者決定】

- F-80 サムネイル一覧でページをドラッグして順番を変えられる。
- F-81 ページを削除できる（複数選択可）。
- F-82 空白ページを追加できる。大きさは前後のページに合わせるのが既定で、A4 縦・横なども選べる。
- F-83 別の PDF のページを、指定した位置に挿入できる【作成者判断：「ページの追加」に含めた】。
- F-84 ページを 90 度単位で回転できる【作成者判断】。

### 4.10 ヘッダー・フッター【依頼者決定】

- F-90 ページの上部（ヘッダー）と下部（フッター）に、左・中央・右の 3 か所ずつ文字を入れられる。
- F-91 入れられる内容：自由な文字、ページ番号、総ページ数、日付、ファイル名。
- F-92 フォント、サイズ、色、ページ端からの距離を指定できる。
- F-93 適用するページ範囲（全ページ、範囲指定、先頭ページを除く、奇数・偶数）を指定できる。
- F-94 ページ番号の開始番号を指定できる。
- F-95 このアプリで付けたヘッダー・フッターは、後から設定画面を開いて内容を変更、または一括削除できる。ページの並べ替え・追加・削除をした場合、ページ番号は振り直す。
- F-96 他のソフトで作られた PDF に最初からあるヘッダー・フッターは、通常の文字として 4.2 の方法でページごとに編集できる。加えて、ページ上端・下端の指定した高さの範囲にある文字を、指定ページ範囲で一括削除できる。その上で新しいヘッダー・フッターを付け直す【作成者判断：依頼者に要確認。9 章の確認事項 1】。

### 4.11 共通の編集操作

- F-100 元に戻す・やり直し（Ctrl+Z / Ctrl+Y）が、すべての編集操作に効く。最低 50 段階【作成者判断】。
- F-101 追加したテキスト・画像・図形は、選択、移動、複製、削除、重なり順の変更ができる。
- F-102 コピー・切り取り・貼り付けができる。
- F-103 文書内の文字を検索できる【作成者判断】。

### 4.12 保存

- F-110 「上書き保存」と「名前を付けて保存」がある。
- F-111 保存は、別の一時ファイルに書き出し、正しく開けることを確かめてから元の場所に置き換える。途中で失敗しても元のファイルは壊れない。
- F-112 その文書に対する最初の上書き保存の時に、元のファイルを同じフォルダに「元の名前.bak.pdf」として残す【作成者判断】。
- F-113 保存に失敗した場合（ファイルが他のソフトで開かれている、書き込み権限がない、空き容量がない等）、原因と対処を日本語で表示し、別の場所への保存を提案する。編集内容は失わない。
- F-114 未保存の変更がある状態で閉じようとしたら確認する。
- F-115 元の PDF にあったしおり、リンク、注釈、フォームの入力欄は、編集していない限り保存後も残す。
- F-116 保存した PDF は Adobe Acrobat Reader、Microsoft Edge、Google Chrome で問題なく開ける。

## 5. 品質要件

依頼者が「これが起きたら失敗」としたのは次の 4 点である。【依頼者決定】

1. 起動できない
2. 動作が重すぎる
3. 出力に失敗する
4. 長方形・楕円（枠線と塗りつぶしを指定）の追加ができない

これを次の基準に置き換える。数値は作成者判断。基準機は「メモリ 8GB、SSD、5 年以内の一般的な事務用ノート PC」とする。

### 5.1 起動

- Q-01 追加のソフト（ランタイム等）を入れていない Windows 10 / 11 で、展開して実行するだけで起動する。
- Q-02 管理者権限を求めない。
- Q-03 ダブルクリックからウィンドウ表示まで 3 秒以内（2 回目以降）。
- Q-04 日本語や空白を含むフォルダ、OneDrive 配下、USB メモリ上からでも起動する。
- Q-05 起動に失敗した場合、黙って終了せず、原因を示すメッセージを出し、ログを残す。

### 5.2 動作の軽さ

- Q-10 100 ページ・20MB の PDF を開いて最初のページが出るまで 2 秒以内。
- Q-11 スクロール、拡大・縮小、文字入力で引っかかりを感じない（入力から表示まで 0.1 秒以内を目安）。
- Q-12 500 ページの PDF でも、開く・スクロール・ページ並べ替えができる。表示中のページの近くだけを描画する。
- Q-13 待ち時間が 1 秒を超える処理は進行状況を表示し、画面が固まらない。

### 5.3 出力の確実さ

- Q-20 4.12 の保存要件を満たす。
- Q-21 動作確認用の PDF 一式（Word、Excel、PowerPoint、Google ドキュメントの各出力、スキャン PDF、パスワード付き、フォーム付きなど 20 種以上）を用意し、全機能を掛けた後の保存結果が Q-22 を満たすことを自動テストで確認する。
- Q-21a 動作確認用 PDF は、作る人が中身を新しく書き起こして作り、リポジトリに置く。依頼者が実際に扱う文書は公開リポジトリに置かず、段階 3 の実用確認のときに依頼者の手元で試す【作成者判断】。
- Q-22 保存結果が、PDF の検査ツールでエラーなく読め、F-116 の 3 つの閲覧ソフトで開ける。
- Q-23 アプリが異常終了しても、元のファイルは壊れない。

### 5.4 その他

- Q-30 配布物の大きさは展開前で 150MB 以下を目安とする。
- Q-31 処理できない PDF や操作に当たった場合、アプリは落ちずに、できない理由を表示する。

## 6. 非目標（初版ではやらないこと）

- スキャン PDF の文字認識（OCR）と、その文字の打ち替え
- 縦書き・段組み・表の中の文章の、確実な流し直し
- 編集した段落より下の内容の自動押し下げ、ページをまたぐ文章の流し直し（Word のような文書全体の組み直し）
- 足りない文字だけを別フォントで補うこと
- 表の構造の編集（行・列の追加など）
- フォームの入力欄の作成・編集、電子署名の付与
- PDF から Word など他形式への変換
- 複数 PDF の一括処理
- Mac、Linux、スマートフォン、ブラウザ版
- 自動アップデート
- 英語など日本語以外の画面

## 7. してはいけないこと

動いていても、次が起きたら失敗とみなす。

- 元のファイルを壊す、または編集内容を黙って失う
- 黒塗りした下の文字が、保存後の PDF から取り出せる
- PDF の内容や利用状況を外部に送信する
- 編集していない部分の見た目が変わる
- 文字化けした PDF を、警告なしに保存する（選んだフォントにない文字が空白や四角になる場合を含む）

## 8. 作り方【すべて作成者判断】

依頼者から、使用言語と部品の選定は作成者に任されている。

### 8.1 選定

| 役割 | 選んだもの | 理由 |
|---|---|---|
| PDF の読み書き・描画 | PyMuPDF（MuPDF） | 無料の部品の中で、既存文字の位置と書式の取得、文字データごと消す黒塗り、枠内での文章の流し込み、フォントの部分埋め込み、ページ操作、画像・図形の描画を 1 つで賄える。描画が速い |
| 言語 | Python 3.12 以降 | PyMuPDF を最も直接に使える |
| 画面 | PySide6（Qt） | Windows で軽く動き、ページ上での直接編集や大きな文書のスクロールを作りやすい。無料で配布できる |
| 配布形式 | フォルダ一式を zip にしたもの。展開して `PDF-editor.exe` を実行 | 1 ファイルにまとめる形式は起動のたびに展開が走り遅くなるため、Q-03 を満たせるフォルダ形式にする |
| 公開場所 | GitHub の公開リポジトリ。配布物は Releases に置く【公開は依頼者決定】 | 下記のライセンス条件を満たせ、URL を伝えるだけで配れる |

### 8.2 ライセンス

PyMuPDF は AGPL-3.0 で提供されており、これを組み込んだアプリを配る場合、アプリ全体のソースコードを同じ条件で公開する必要がある。依頼者は公開に同意しているため、本アプリは AGPL-3.0 で公開する。

### 8.3 検討して選ばなかった案

- ブラウザ技術（Electron / Tauri と pdf.js、pdf-lib）：表示と追記は得意だが、既存文字の打ち替えと、文字データごと消す黒塗りを自前で作る量が大きい。Electron は配布物が大きく起動も遅くなりやすい。
- C#（WPF）と無料の PDF 部品：Windows との相性は良いが、既存文字の編集と流し直しを賄える無料部品が見当たらない。

### 8.4 文字の打ち替えの実現方針

1. ページから文字の位置・フォント・サイズ・色を取り出し、行の並びと間隔から段落を推定する。
2. 編集が確定した段落について、元の文字だけを PDF から取り除く（背景の図形や画像は残す）。
3. 同じ枠に、編集後の文章を元の書式で流し込み、使ったフォントを部分埋め込みする。
4. 元のフォントが PC にあればそれを使い、なければ 4.4 の置き換え設定に従う。

### 8.4a 選んだ部品だけでは足りず、自作が要る部分

別の技術者による下読みで、次が分かっている。

- 黒塗り：PyMuPDF の黒塗り機能は、注釈には手を付けず、一部だけ掛かる線画は残すか全体を消すかの二択である。F-76、F-77 を満たすには補う処理が要る。フォームの入力欄と、ページ内に埋め込まれた部品の中の文字が確実に消えるかは未確認で、試作で確かめる。
- 文字の除去：範囲との重なりで判定されるため、行間の詰まった隣の段落の文字を巻き込むおそれがある。除去範囲を文字単位で絞る工夫が要る。
- 日本語の折り返し：PyMuPDF の枠内流し込みが日本語の禁則処理に対応しているという記述は確認できていない。対応していなければ、折り返し位置を自前で決める処理を作る（F-12）。
- 権限パスワード：PyMuPDF は編集制限だけの PDF を制限を無視して開くため、パスワードを求める動作はアプリ側で作る。
- 複数書体を 1 ファイルに収めたフォント（游ゴシック、MS ゴシック、メイリオなど）から目的の書体を選んで埋め込めるかは未確認。試作で最初に確かめる。

### 8.5 作る人に任せること

- 画面の細かな配置と見た目（左にサムネイル、中央にページ、上にツールバー、右に書式設定という一般的な構成を基本とする）
- 段落推定の具体的な方法
- 内部のデータの持ち方、元に戻す仕組みの実装
- 自動テストの構成
- 配布物を作る道具（PyInstaller、Nuitka など）の選択。Q-01〜Q-04、Q-30 を満たすこと

## 9. 既知のリスクと確認事項

### リスク

- **起動時の警告**：署名のない実行ファイルは、Windows の SmartScreen が「PC が保護されました」と警告を出すことがある。署名には年単位の費用が掛かるため初版では行わず、配布ページに回避手順（「詳細情報」→「実行」）を載せる。組織の PC で実行ファイルの実行自体が制限されている場合は起動できない。配布前に、配布先の代表的な PC で起動確認を行う。
- **段落推定の誤り**：PDF には段落の情報がないため、推定が外れることがある。F-13 の結合・分割で利用者が直せるようにする。
- **書式の完全な再現**：字間の微調整や特殊な組み方は、打ち替え後に完全には再現できない場合がある。編集していない段落には影響しない。
- **游ゴシック・游明朝の埋め込み**：下読みで Windows 11 上のフォントファイルを確認し、游ゴシック、游明朝、MS ゴシック、MS 明朝、メイリオは編集可能な埋め込みが許可されていた。BIZ UD ゴシック・明朝は「印刷・プレビューのみ」で、F-23 により候補から外れる。

### 依頼者に確認したいこと

1. 既存のヘッダー・フッターの「変更」（F-96）：他のソフトで付けられたものは「上端・下端の範囲を一括削除して付け直す」方式でよいか。
2. 配布先の PC：学校や職場が管理している PC を含むか。含む場合、実行ファイルの実行制限やウイルス対策ソフトで起動を止められるおそれがあり、段階 1 での起動確認の進め方と、署名費用を掛けるかどうかの判断に関わる。

## 10. 進め方の案【作成者判断】

一度に全部は作らず、動くものを早く配って確かめる。

| 段階 | 内容 | 確かめること |
|---|---|---|
| 1 | 開く・表示・保存、ページ操作、配布形式の確立 | 配布先の PC で起動するか、重くないか（失敗条件 1〜3） |
| 2 | テキスト・画像・図形の追加、黒塗り | 失敗条件 4、黒塗りの完全性 |
| 3 | 既存文字の打ち替え、フォント置き換え | 実際の文書で段落編集が実用になるか |
| 4 | ヘッダー・フッター、仕上げ | 全体の使い勝手 |

段階 3 が最も難しいため、段階 1 と並行して、実際の PDF で打ち替えの小さな試作を行い、実現性を先に確かめる。試作では 8.4a の未確認事項（日本語の折り返し、フォントの書体選択、黒塗りの漏れ）を先に確かめる。
